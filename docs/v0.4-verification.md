# 0.4.0 验证记录

日期：2026-11-08（Asia/Taipei）。设备：peridot / Android 16 / HyperOS OS3.0。

## 官方账号网页容器与登录态

从官方账号 APK 解析发现：

- `com.xiaomi.account.ui.PassportJsbWebViewActivity` 已导出，允许外部应用打开 HTTPS 的 `.xiaomi.com` / `.mi.com` 页面。
- 支持 `cookie_fill_login_service_id`、`cookie_fill_cookie_set_url`、`cookie_fill_account_device_params` 参数。
- 组件内部 `collectUrlLoadPrepareTasks` 创建 `CookieFillAutoLoginULPT`，由官方组件负责读取系统账号的服务会话并填充网页。
- 官方支付网页未登录时的服务重定向确认服务标识为 `mipaycom`。

素卡包固定调用上述组件，传入：

```text
cookie_fill_login_service_id=mipaycom
cookie_fill_cookie_set_url=https://m.mipay.com
cookie_fill_account_device_params=true
action_bar_style=native
```

页面分别为：

- `https://m.pay.xiaomi.com/home/passManage?from=webEntry`
- `https://m.pay.xiaomi.com/deduct/recission?from=webEntry`

这两个官方 `.xiaomi.com` 地址由官方服务器重定向到 `m.mipay.com`，不伪造来源或调用身份，不跳过组件的域名校验。

在本机已登录小米账号的情况下，账号组件直接显示：

- 支付密码：修改支付密码、找回支付密码。
- 免密 / 自动续费：小额免密支付设置、免密金额、自动扣款列表管理。

没有展示重新登录页，也未输入账号密码。未复制、读取、打印或保存官方账号的令牌与 Cookie。应用不请求账号权限或联网权限。后续业务仍由官方网页与服务决定，未提交变更。

## 保护实现

完整页面 `ProtectionActivity` 设置验证方式；完整页面 `PatternActivity` 设置/验证图案。指纹使用 Android `BiometricPrompt`，保留系统原生验证窗口。无跳转到安全中心应用锁设置。

图案两次确认，随机盐 + PBKDF2-HMAC-SHA256（120000 轮、256 位），恒定时间比较。连续 5 次错误暂缓 30 秒。配置仅存在应用私有 SharedPreferences，不保存明文图案。后台哈希计算结束后，仅在页面仍有效时提交设置。

`WalletApp` 统计应用内活动页面，全部退到后台时清除内存解锁状态。`SecureActivity` 在身份验证完成前隐藏内容，取消则退出；进程启动默认未解锁。应用内页面切换不主动清除会话。开启本地保护不代表官方智能卡本身受到额外保护。

所有页面设置 `FLAG_SECURE`，不显示系统截图或最近任务预览内容。

## 边界

只在当前手机上验证，未测试其他 ROM、未登录系统账号、过期账号会话、官方账号组件缺失等情况。官方组件可以要求重新验证身份，不能承诺永久免登录。

手势绘图面板依赖触摸输入，尚未提供无障碍替代输入；需要无障碍操作时应使用系统身份验证方式。应用保护默认关闭，由用户决定是否开启。

## 本地保护真机结果

- 全屏手势设置：两次相同图案确认后成功启用。
- 离开应用后返回：出现全屏解锁页。
- 错误图案：被拒绝，停留在解锁页。
- 正确图案：成功返回卡包首页。
- 指纹方式：已显示 Android 原生身份验证窗口；未代替用户完成指纹识别。
- 测试完成后：已关闭素卡包本地保护，留给用户自行选择验证方式。

没有修改系统锁屏、系统应用锁或官方钱包原有的保护配置。

最终安装包已从素卡包「设置」内实际点击支付密码及免密/自动续费入口，前台均为官方账号组件，页面视觉检查确认已登录且内容正常。没有拉起外部浏览器或官方钱包。
